版本以 `src/Quantum.Zju.Plugin.Cas/plugin.json` 为准。1.0 之前，兼容修复使用补丁版本，兼容功能使用次版本，不兼容合约须通过明确记录的次版本迁移。对外集成面包括插件 ID、RPC 能力、请求与响应以及生命周期行为。

## 0.6.0 — 尚未发布

- 使用宿主设置页按钮样式。登录前只显示**登录**，登录后显示账号标识和**退出**。
- 检测 CAS 回跳，验证账号后自动关闭原生登录窗口。
- 在账号响应中新增可选的 `username` 字段，值来自 CAS 票据验证。现有账号与服务票据请求保持与 0.5.0 兼容。
- 登录页过期时使用新的流程地址自动重开一次；再次过期显示**重新打开**，避免循环跳转。
- 登录前及已验证会话交接后清理 CAS 范围的原生浏览器 Cookie。退出会释放独立 HTTP 会话，再次登录可使用其它账号。学校登录使用标准服务流程，不添加 `renew=true`。
- 诊断仅记录阶段名称、错误代码和异常类型，不记录账号、密码、Cookie、票据或响应正文。
- 分别生成可复现的 Windows 和 macOS ZIP，附 SDK 元数据、SHA-256 校验和、软件物料清单及构建来源记录。CI 在打包及固定宿主检查通过后才保留候选产物。

兼容性：使用 SDK `0.3.0-rc.3`，Desktop 宿主须实现 `quantum.settings/accounts`。安装包包含平台专用的原生适配器，须选择与宿主操作系统一致的 ZIP，不提供跨平台通用原生 ZIP。不需要数据库或配置迁移；升级后重新进入账号设置并登录。

恢复：登录、账号显示或服务票据获取失败时停止推广，重新安装不可变的 0.5.0 Windows 安装包，或使用新版本进行向前修复。0.5.0 仍有旧的手动确认及本地断开限制。外部集成继续负责各自站点的会话。不得替换已有版本的安装包或移动已发布标签。

### 发布门槛

按仓库流程通过 PR 合并。对受保护历史中的同一提交完成 Windows 与 macOS 验证，保留两个 CI 产物，并在该已验证提交上创建带签名的附注标签 `v0.6.0`。直接推广这些安装包，不重新构建。向插件市场提交 Windows 安装包前，核对各公开下载的校验和、源提交和 SDK 元数据。原生凭据处理可能要求市场人工审核；提交成功或待审核不等于已发布。

运行 `.ci/Build.ps1` 和 `.ci/Verify-Host.ps1`。打包输出 `artifacts/<platform>/quantum.zju.plugin.cas-0.6.0-<platform>.zip`，以及各平台的发布元数据、校验和、SPDX 清单和构建来源文件。本地构建会明确记录工作区是否有未提交修改；只有干净且验证成功的 CI 输入可以推广。源码、检查与产物链接以及实际验收结果保存在发布和 PR 记录中，不进入源码版本控制。

## 0.5.0 — 2026-11-06

Windows 插件市场版本，提供 `zju.cas.account` 与 `zju.cas.service-ticket`，使用 SDK `0.3.0-rc.3`。业务集成自行处理回跳、站点会话和数据读取。源码：[`711bb453`](https://github.com/XmmShp/Quantum.Zju.Plugin.Cas/commit/711bb453a8ff48b1dc967cf7918cf11bb2bdf6f8)。此版本未包含或验证 macOS。
